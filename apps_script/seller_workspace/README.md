# Seller Workspace Apps Script — деплой и тестирование

Container-bound Google Apps Script рабочей книги продавца — привязывается к
конкретной рабочей книге продавца (или к мастер-шаблону перед выпуском новой
копии). Включает две функции: карточку товара (см.
`docs/superpowers/specs/2026-07-22-product-card-apps-script-design.md`) и
форму профиля продавца (см.
`docs/superpowers/specs/2026-08-07-seller-profile-form-apps-script-design.md`).

## Деплой (ручной, тулинга/clasp нет)

1. Открыть рабочую книгу (`catalog_template_v1.xlsx`, импортированную в Google
   Sheets, либо уже существующую копию продавца).
2. `Расширения → Apps Script` — откроется Script Editor привязанного проекта
   (если ещё не создан — Google создаст пустой проект автоматически).
3. Заменить содержимое `appsscript.json` (иконка шестерёнки слева →
   `Показать файл манифеста`) на содержимое `apps_script/seller_workspace/appsscript.json`
   из этого репозитория.
4. Создать/заменить файл `Code.gs` — вставить содержимое
   `apps_script/seller_workspace/Code.gs`.
5. В строке `API_BASE_URL` заменить `https://CHANGE_ME.example.com/api/v1` на
   реальный адрес backend.
6. Создать HTML-файл `Card` (`Файл → Создать → HTML-файл`, имя ровно `Card`) —
   вставить содержимое `apps_script/seller_workspace/Card.html`.
7. Создать файл `Profile.gs` (`Файл → Создать → Скрипт`, имя ровно `Profile`) —
   вставить содержимое `apps_script/seller_workspace/Profile.gs`.
8. Создать HTML-файл `Profile` (`Файл → Создать → HTML-файл`, имя ровно `Profile`) —
   вставить содержимое `apps_script/seller_workspace/Profile.html`.
9. Сохранить проект (`Ctrl+S`/`Cmd+S`), закрыть Script Editor, обновить страницу
   таблицы — в меню должен появиться пункт «GreenMarket».

## Мобильное приложение Google Sheets — ограничение

Кастомное меню («GreenMarket» → «Открыть карточку»/«Добавить товар»/«Личный кабинет»),
которое создаёт `onOpen()`/`createMenu()`, а также модальный диалог карточки
(`Card.html`) — часть desktop-only UI Google Sheets. В нативном мобильном приложении
Google Sheets (Android и iOS) кастомные меню контейнерных скриптов не отображаются —
это ограничение платформы, не баг данной реализации.

**Решение для Stage 1 (согласовано с коллегой, 2026-07-24):** Workspace Add-on не
разрабатываем, обход ограничения мобильного приложения не делаем. Основной способ
работы с карточкой — браузерная версия Sheets (ПК или планшет); с телефона — через
мобильный браузер в режиме «Версия для ПК» (Chrome/Safari → меню → Request Desktop
Site), либо напрямую редактируя строки таблицы без карточки.

**Stage 2:** карточка товара, загрузка фото, управление каталогом и публикация
постепенно переезжают в Seller Cabinet (уже мобильный веб) как основной интерфейс
продавца; Google Sheets остаётся источником данных и инструментом массового
редактирования.

## Ручное тестирование (чек-лист)

### Карточка товара

- [ ] При открытии книги в меню есть «GreenMarket» → «Открыть карточку» / «Добавить товар» /
      «Личный кабинет».
- [ ] «Открыть карточку» на строке заголовка (строка 1) — предупреждение, карточка не открывается.
- [ ] «Открыть карточку» на пустой строке без данных (в том числе когда лист «Каталог» вообще
      без товаров) — предупреждение с подсказкой использовать «Добавить товар», карточка не
      открывается и новая строка не создаётся.
- [ ] «Открыть карточку» на заполненной строке — все поля (наименование, группа, позиция, цена,
      единица, остаток, описание, характеристики) заполнены значениями из ячеек; если в
      ячейке «Фото» есть id — превью загружаются.
- [ ] «Добавить товар» — карточка открывается пустой; после «Сохранить» — новая строка
      добавляется в конец листа «Каталог» с корректными значениями.
- [ ] При первом действии (сохранение/загрузка фото/«Личный кабинет») карточка запрашивает
      код активации — всплывающее окно `ui.prompt` «Активация доступа» (не сырой `access_token` —
      см. `docs/superpowers/specs/2026-07-23-seller-activation-auth-design.md`); реальный код,
      выданный `backend/scripts/issue_activation_code.py`, обменивается на `access_token`,
      который сохраняется в `PropertiesService`; повторные действия код уже не запрашивают.
- [ ] «Личный кабинет» — открывает модальный диалог со ссылкой на Seller Cabinet
      (`?token=...`); переход по ссылке показывает реальные данные этого продавца.
- [ ] «Добавить фото» — выбор файла (jpg/png/webp) → превью появляется, файл реально
      загружен (проверить `GET /api/v1/publications`-совместимый способ или напрямую в БД/S3,
      что `Photo` с этим `s3_key` создан и привязан к `seller_id` продавца).
- [ ] «Удалить» на превью — фото пропадает из карточки; после «Сохранить» — id пропадает из
      ячейки «Фото» (публикация синхронизирует `SellerProductPhoto` без него).
- [ ] Загрузка файла неподдерживаемого типа (например `.pdf`) — сообщение об ошибке
      (`alert`), карточка остаётся открытой, остальные данные не потеряны.
- [ ] Ввод заведомо неверного/просроченного/уже использованного кода активации — alert
      «Код активации недействителен...», карточка предлагает ввести код заново при следующем
      действии (код не сохраняется в `PropertiesService`, если активация не удалась).
- [ ] После успешной активации — отзыв доступа администратором (`Seller.is_active = FALSE`)
      → следующее действие получает `403 SELLER_ACCESS_DENIED`, `PropertiesService` автоматически
      чистит сохранённый `access_token` (см. `handleApiResponse`), следующее действие снова
      запрашивает код активации.
- [ ] «Личный кабинет» при мёртвом сохранённом токене (отозвать доступ администратором либо
      подложить мусор в `GREENMARKET_ACCESS_TOKEN` через Расширения → Apps Script → Свойства
      документа) — alert «Сохранённый доступ … больше не действует», сразу запрос кода
      активации; после ввода верного кода открывается диалог со ссылкой, и ссылка рабочая.
      Без этой проверки (`isAccessTokenRejected_`) пункт вёл в тупик: ссылка выдавалась
      с мёртвым токеном.
- [ ] «Личный кабинет» при недоступном backend (например, временно указать неверный
      `API_BASE_URL`) — ссылка всё равно выдаётся, сохранённый токен не стирается
      (отзыв только на явный `403`).
- [ ] После «Сохранить» с реальными данными — публикация каталога (`POST /api/v1/publications`)
      проходит без ошибок валидации по колонке «Фото».
- [ ] Строка без фото — публикация проходит успешно (не 422), товар сохраняется, но в каталог
      покупателя не попадает; Seller Cabinet показывает его в блоке «Не попали в каталог — нет фото».
      После добавления фото и повторной публикации товар появляется в каталоге.
- [ ] Выбор второго фото сразу после первого (пока первое ещё грузится) — поле выбора файла
      заблокировано до завершения текущей загрузки (защита от гонки, добавлена по итогам ревью).
- [ ] Открытие карточки на строке, где значение товарной группы/позиции больше не входит в
      текущие справочники (устаревшая позиция) — значение остаётся выбранным (не сбрасывается
      на пустое), а не исчезает молча (защита от рассинхрона, добавлена по итогам ревью).

### Профиль продавца

- [ ] В меню «GreenMarket» есть пункт «Профиль продавца».
- [ ] На неактивированной книге пункт спрашивает код активации; отказ (Cancel) —
      диалог не открывается, ошибок нет.
- [ ] Диалог показывает реальные значения профиля этого продавца; название продавца
      и статус — только для чтения (полей ввода для них нет).
- [ ] Профиль без телефона у продавца с учётным номером в платформе — под полем
      «Телефон» видна подсказка «В учётной записи указан … — подставить»; клик
      подставляет номер в поле, но пока не нажато «Сохранить», на сервере ничего
      не меняется (проверить `GET /api/v1/seller/profile`).
- [ ] Профиль с заполненным телефоном — подсказки нет.
- [ ] Изменение одного поля → «Сохранить» → диалог закрывается, в таблице toast
      «Профиль сохранён», а `GET /api/v1/seller/profile` отдаёт новое значение.
- [ ] Повторное «Сохранить» без правок — статус «Изменений нет», запрос к API не уходит
      (проверить по журналу выполнений Apps Script), диалог остаётся открытым.
- [ ] Изменения видны покупателю: `GET /api/v1/catalog/sellers/{id}` отдаёт новые значения.
- [ ] Изменения попали в ленту: `GET /api/v1/admin/profile-changes` (с токеном админа)
      содержит запись с `author_role = "SELLER"` и именами изменённых полей.
- [ ] Очистка заполненного поля (стереть текст → «Сохранить») — поле пустое и в
      `GET /api/v1/seller/profile`, и в карточке покупателя.
- [ ] Незаполненные обязательные поля — в форме под кнопками строка «Покупатель не увидит: …»,
      она же в toast'е после сохранения; кнопка «Сохранить» при этом работает.
- [ ] Деактивация продавца администратором (`PUT /api/v1/admin/sellers/{id}/deactivate`) →
      следующее сохранение даёт alert с ошибкой доступа, форма остаётся открытой с введённым
      текстом, сохранённый токен стёрт — следующее действие в книге снова спросит код активации.
- [ ] Недоступный backend (временно указать неверный `API_BASE_URL`) — alert об ошибке,
      введённые данные в форме не потеряны.

## Инфраструктурное предусловие

S3-бакет (`S3_BUCKET`/`S3_REGION` в `.env` backend) должен быть публичным на чтение —
иначе превью в карточке и `GET /api/v1/photos` вернут URL, которые не откроются в
браузере. Настройка — на AWS-консоли, вне этого репозитория.
